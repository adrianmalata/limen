## 1. The start queue today

- Module: `src/runtime/start-queue.ts` (542 lines).
  - One queue and one gate serve the whole seat; there is no daemon (`:26-28`).
  - Entries are `<seat>/start-queue/entries/<id>.json`, each `{id, jobDir, label, priority, queuedAt, pid}`
    (`:32-39`, `:50-51`).
- Entering (`enterStartQueue`, `:161-168`):
  - A job queues when the gate is on or a rule holds its priority.
  - It returns `{ since: new Date().toISOString(), detail: null, ahead: null }`.
  - The wrapper calls it (`src/runtime/wrapper.ts:81`; a group member skips it) and writes it with the handshake:
    `transition` from `starting` to `running`, setting `identity`, `queued` and `scope` (`:87-91`).
  - So a queued job is state `running` with `queued !== null`.
- Waiting (`waitForStart`, `:182-203`, and `pollQueue`, `:206-250`):
  - `since` comes from `record.queued.since` (`:185`), and `queuedAt = Date.parse(since) || Date.now()` (`:191`).
  - Each poll runs `enqueue` (`:332-337`), then `decide` (`:338-385`), then sleeps `pollMs()`
    (`:247`; 5 s, `:52-55`).
  - Decision kinds:
    - `rules <versions>`: a rule holds the job (`:150-155`, `:342-344`).
    - start at once with "the gate is off" (`:345-347`).
    - `ahead`: other jobs come first; the last reading is shown (`:348-350`).
    - `gate`: only the head samples the load (`:351-357`).
    - `settle` (`:358-366`).
    - `raced`: re-checked under the queue's lock, which also writes `last-start` (`:369-384`).
  - Order: priority, then `queuedAt`, then id (`:411-412`).
  - `liveEntries` drops entries whose wrapper is dead or whose job is not `running` (`:415-435`).
- What is recorded while a job waits:
  - `queued {since, detail, ahead}` is rewritten when the kind or `ahead` changes or `DETAIL_REFRESH_MS` (60 s)
    passed (`:231-246`). Each rewrite builds a new `Queued` from `since` and the decision (`:237`).
  - A `queued: …` log line goes out on the first decision and on each change of rule kind (`:242-244`).
  - The seat's `start-queue/reading` and `last-start` files (`:353`, `:379`).
  - Type: `Queued = { since: string; detail: string | null; ahead: number | null }` (`src/job/record.ts:89`).
- What ends the wait (`QueueEnd = "started" | "stopped" | "gone"`, `:171`):
  - `started` writes `start-notice` and `start queue: started after <wait>` when the job waited (`:386-398`).
  - `stopped`: the stop signal aborts the wait; `limen stop` first sets `stopRequested` (`src/job/stopping.ts:94-98`),
    and the wrapper finalizes `stopped` (`wrapper.ts:100-105`).
  - `gone`: the record is missing; the wrapper returns with no record and no engine (`wrapper.ts:97-99`).
  - A record check that fails with an error other than ENOENT throws `QUEUE_RECORD_UNREADABLE` (`:312-330`). That
    error reaches `failInternalJob`, which records `failed` (`wrapper.ts:353-359`).
  - `leaveQueue` removes the entry and sets `queued: null` (`:259-269`). `finalizeJob` also sets `queued: null`
    (`src/job/finalize.ts:93`), so no record keeps the wait once the job has left the queue.
- A-036's path is still open:
