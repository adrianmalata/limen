In short: the wrapper keeps one activity string (`src/runtime/wrapper.ts:488`, `:509`, `:522-523`). Every
`tool_execution_end` becomes the activity `wait` (`src/runtime/stream.ts:46-48`), and the stall rule acts only while the
activity is `tool` (`src/runtime/wrapper.ts:314-315`). Pi 1.5.1 runs the tools of one message in parallel by default and
tags every start and end with `toolCallId`. The stream parser drops that id today. The only other reader of the
wrapper's activity is the progress file (status, picture, wake hook), which shows `wait` while the second tool runs.
